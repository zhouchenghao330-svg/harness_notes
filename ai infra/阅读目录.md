## 一、这本东西最适合给你补什么？

你现在很多东西其实已经接触到了：

`prefix cache / vLLM / context / tool call / agent loop / streaming / 并发 / 模型 API / runtime`

但其中有些概念你现在更多是从**应用层经验**理解。

比如你知道：

```
长 context → 慢
prefix cache → 能省东西
batch → 提高吞吐
KV cache → 很吃显存
tool call 等待 → Agent 整体变慢
vLLM → 会调度请求
```

这本书会继续往下问：

```
为什么？

到底慢在哪？

慢的是：
计算？
显存带宽？
KV 读取？
权重读取？
CPU launch？
网络？
排队？

优化以后理论最多能快多少？
```

这是它最值钱的地方。

作者整本书反复强调的就是一种方法：

> **先计算物理上限，再看实际系统离上限差多远。**

例如不是看到 GPU 有 1000 TFLOPS，就认为某模型一定很快，而是继续算：权重有多少 GB、HBM 带宽多少、一次 decode 要搬多少数据、KV 要读多少。[GitHub](https://github.com/bojieli/ai-infra-book)

这套思维我觉得你挺值得学。

# 十二、它和你现在看的 Agent Harness 不是一个东西

这个区别非常重要。

你最近在看 Hermes/Pi 那套东西，主要在研究：

```
模型下一步做什么？

什么时候 tool call？

什么时候 compact？

什么时候 retry？

什么时候结束？

memory 怎么存？

crash 怎么恢复？

context 怎么管理？
```

这是：

> **Agent Runtime / Harness Design**

而这本 AI Infra 更偏：

```
这次模型调用为什么花 3 秒？

为什么 context 长了以后显存上升？

为什么 batch 能提高 throughput？

为什么 prefix cache 能省 prefill？

为什么 tool 等待期间 KV 还占显存？

为什么 sandbox 一直保留很浪费？

为什么 P/D 要拆？

为什么某个优化 GPU 快了，但端到端没快？
```

这是：

> **AI Systems / Infra**

两者拼起来其实很漂亮：

```
             Agent Design
                  │
          Harness / Runtime
                  │
       Context / Tool / Memory
                  │
────────────────────────────────
                  │
          Model Serving
                  │
       Scheduling / KV Cache
                  │
        CUDA / Runtime
                  │
        GPU / Memory
```

你现在上面三层已经积累不少了。

**这本书最大的作用，是让你开始把下面三层补出来。**

所以我的建议是：**学，而且近期就可以学；但不要通读。先读 1 → 3.1/3.2 → 8 → 11。** 这四块我觉得对你现在的收益明显高于继续随机找另一个 Agent 项目读源码。
