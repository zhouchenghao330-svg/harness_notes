# 组件 02：AI Infra 全景与六层结构

> 状态：已共同阅读。这里只保留定位图；资源数量级、调度与缓存分别在后续组件展开。

## 1. 学习目标与边界

建立从 Agent 应用到底层硬件的整体地图，重点阅读第 1 章 1.1。不在本组件展开各层的内部优化。

## 2. 先用直白的话讲

六层不是六个依次运行的程序，而是观察同一次任务的六个视角。向下追，任务要求逐渐落实为请求、计算、状态和数据搬移；向上看，资源限制决定能否运行、能多快完成。

## 3. 最小运行链

```text
应用与任务：要完成什么，正确性、时限和成本要求是什么
  ↓
模型与负载：用什么模型，输入输出多长，请求何时到来
  ↓
训练与推理系统：路由、排队、Batch、状态管理
  ↓
算子与编译运行时：把模型运算编排并提交执行
  ↓
处理器与存储：CPU/GPU 计算，权重、KV 和临时数据驻留
  ↓
互联与数据中心：设备之间的数据传递和资源部署
```

这些箭头表示分析层次，不表示一次请求必经六个串行程序。网络也不只作用于最底层；单机请求可能没有跨机通信。

## 4. 关键输入、输出和状态

一次 Agent 请求中，Harness 组装上下文、调用模型、检查并执行工具、把结果写回下一轮；模型服务选择推理实例，实例内部调度 Prefill/Decode；CPU 运行时提交工作，GPU 读取权重和 KV 并生成 token。文件、进程和工具执行仍依赖操作系统，不会因为模型输出了代码就自动发生。

## 7. 与 Agent Harness 的连接

Harness 主要回答“下一步做什么、模型看到什么、工具如何执行”；AI Infra 继续追问“这一步为何耗时、占用什么资源、数据经过哪里”。Harness 不等于推理服务；服务路由器选实例，实例内部调度器安排执行。

## 9. 已确认结论

- 实验 1-1 的六轮模型生成墙钟合计约 18.94 秒，工具子进程约 16.37 秒，循环约 35.42 秒。两者在该控制链中顺序执行，不能假设直接重叠。
- 工具内部约 4.31 秒的 CUDA event 窗口嵌在工具墙钟内，不能重复加总，也不能当作 GPU 忙碌时间。
- 六次验证通过，但候选代码的 AST 未改变；“工具成功”不等于“任务优化成功”。
