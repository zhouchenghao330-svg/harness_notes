# AI Infra 共同学习共识

> 本文件是 `ai infra` 笔记的总规则。后续开始任何组件前，先阅读本文件与 [[阅读目录]]。

## 0. 学习目标

这套笔记不追求从第 1 章到第 12 章通读，也不把书稿压缩成摘要。

目标是结合 `ai-infra-book` 当前仓库中的正文、计算程序、实验记录和案例，逐步回答：

- 一次模型或 Agent 请求消耗了哪些资源；
- 时间到底花在计算、数据搬移、排队、工具等待还是环境恢复上；
- Context、KV Cache、Batch 和 Prefix Cache 在系统层分别意味着什么；
- 理论上限、估算结果和实际测量为什么不同；
- 一项优化改善了哪一段路径，又引入了什么容量、质量或复杂度成本；
- Agent Harness 的设计最终如何落到模型服务、运行环境和资源调度上。

最终形成一套面向 Agent 工程师的 AI Infra 学习笔记，而不是全书章节摘要。

## 1. 第一轮范围

第一轮严格按 `阅读目录.md` 给出的顺序：

```text
第 1 章
  ↓
第 3 章 3.1 / 3.2
  ↓
第 8 章
  ↓
第 11 章
```

按需回查：

- 第 2 章：模型内部、Attention、KV 和 MoE；
- 第 5 章：算子、CPU/GPU 异步、CUDA Graph 和 Runtime；
- 第 9 章：多卡推理与 Prefill/Decode 分离；
- 第 12 章：端、边、云放置。

暂不主动展开第 4、6、7、10 章。只有主线问题依赖这些章节时才回查。

## 2. 证据层次

每个组件至少检查以下四层材料：

```text
manuscripts/
  概念、问题、公式和叙事主线

calculations/src/infra_calc/topics/
  可复算的数量关系、条件与假设模型

experiments/chXX/
  实际运行、轨迹回放、测量结果与验证范围

case-studies/ + references/
  工程案例、来源和适用边界
```

结论按以下标签区分：

- **正文定义**：书稿明确给出的概念或条件；
- **代码复算**：可从计算程序和固定输入复现；
- **实验观察**：特定模型、硬件和配置下的实测；
- **推导结论**：从已确认材料推出，但不是原文直接声明；
- **待验证**：证据不足或仍需共同阅读。

不能把理论下界写成实测性能，不能把单次实验写成普遍规律，也不能把示意图中的箭头当作真实带宽记录。

## 3. 固定学习流程

每个组件按以下顺序共同阅读：

1. 用直白语言说明它解决什么问题；
2. 建立最小系统模型和术语边界；
3. 追踪一次真实请求或数据流；
4. 列出输入、输出、状态和资源；
5. 拆解关键公式及各项单位；
6. 阅读对应计算代码；
7. 对照实验输入、配置、结果和限制；
8. 比较估算、理论上限和实测差距；
9. 连接到 Agent/Harness 的具体问题；
10. 记录设计取舍、适用条件和未决问题。

先在对话中共同阅读和确认，再补充组件笔记。未经共同确认的推断不得写成确定事实。

## 4. 每个组件必须回答的问题

1. 它解决什么问题？
2. 它位于请求路径的什么位置？
3. 输入、输出和长期状态分别是什么？
4. 主要消耗计算、容量、带宽、网络还是等待时间？
5. 决定数量级的公式是什么？
6. 代码如何表示这些条件和计算？
7. 实验实际测量了什么，没有测量什么？
8. 当前瓶颈是谁，关键路径在哪里？
9. 优化改变了哪一项，又付出了什么代价？
10. 它如何影响 Agent 的延迟、吞吐、成本、恢复或正确性？

## 5. 公式与数字纪律

- 公式使用 Obsidian 支持的 `$...$` 与 `$$...$$`。
- 每个量注明单位，区分 bit、Byte、GB、GiB、Gb/s 和 GB/s。
- 明确容量、带宽、延迟、吞吐和算力不是同一类指标。
- 先写假设，再代入数字；条件变化后必须重新计算。
- 时间下界要说明哪些项能够重叠、哪些项必须串行。
- 端到端时间要区分排队、TTFT、TPOT/ITL、工具等待和恢复时间。
- 成本要区分资源用量、服务账单和失败尝试，不能重复计费。

## 6. 与 Agent Harness 的连接方式

每个组件都保留“与 Harness 的连接”一节，重点连接：

- Context 长度与 KV 状态；
- Agent 多轮调用与 Prefix Cache；
- Tool Call 与关键路径、环境驻留；
- Cancel、Retry、Checkpoint 与资源释放；
- Thinking Budget 与完成质量、延迟和费用；
- 并行工具、分支 Agent 与 Batch、队列及状态寿命；
- Session 恢复与模型状态、工具状态、外部副作用。

这里不重复拆 Harness，而是解释 Harness 的行为如何转化为底层资源和时间代价。

## 7. 笔记状态

- `待共同阅读`：只有范围、入口和问题，尚无确认结论；
- `共同阅读中`：正在讨论，允许记录已确认局部结论；
- `部分完成`：主体已确认，但仍有明确缺口；
- `已共同阅读`：核心问题、代码证据、实验边界和取舍均已确认。

组件索引是状态的唯一总入口。状态变化时，同时更新组件索引和对应组件笔记。

## 8. 仓库与写作纪律

- 以本地 `ai-infra-book` 当前代码为准；
- 正文入口是 `manuscripts/`，但 README 不能代替源码和实验；
- 实验编号存在历史错位时，以实验目录 README 的映射说明为准；
- 不运行高成本 GPU 实验，除非后续明确决定复现；
- 阅读阶段不修改 `ai-infra-book` 源码；
- 只把共同讨论过的内容补入 Obsidian；
- 不确定内容标记为“待验证”，不靠常识补齐。
