# 情景记忆 语义记忆与程序性记忆

> 第②节第二部分及补充讨论。三类记忆已共同阅读并确认理解；Agent 功能分类与框架命名的补充澄清已讲解并确认写入。记录日期：2026-10-12。返回[[00_学习目录|学习目录]]。

**经历、知识、做法**是理解这三类记忆的入口。它们关注记忆内容与功能，而不是保持时间。在 CoALA 框架中，Agent 的长期记忆按情景、语义和程序性组织；这不是人类长期记忆的全部分类。[CoALA 第 4.1 节](https://arxiv.org/html/2309.02427v3#S4.SS1)

## 情景记忆记录具体经历

情景记忆，Episodic Memory，回答「某一次发生了什么」。例如，某次辅导中，助手一次介绍太多概念，用户表示难以理解；改为逐节讲解后，用户确认理解。

这段内容围绕一次交互的情境、行动与结果组织。之后遇到类似任务，可以参考过去的案例。但某次方法成功，不自动证明它在所有情况下都有效。

在人类记忆中，情景记忆涉及具体经历；在 Agent 的功能分类中，可以指以往交互、事件序列与任务轨迹。[Lilian Weng 原文](https://lilianweng.github.io/posts/2023-06-23-agent/#component-two-memory)、[CoALA 原文](https://arxiv.org/html/2309.02427v3#S4.SS1)

## 语义记忆表达事实与知识

语义记忆，Semantic Memory，回答「知道什么」，包括事实、概念、定义与关系。例如「工作记忆涉及当前信息的保持与操作」。

| 内容 | 侧重点 |
| --- | --- |
| 昨天用户在对话中说每天只有 20 分钟 | 某次交互中发生的事情 |
| 用户目前每天可用于学习的时间是 20 分钟 | 关于用户的知识 |

20 分钟是教学假设，不是用户实际学习时间的记录。表格用来说明不同表达角色，不把孤立句子或时间字段当作分类的充分条件。

语义记忆不要求知识对所有人都成立；个人偏好、项目规则也可以是知识。它也不保证内容正确或永久有效。情景记忆侧重「那一次」，语义记忆侧重「知道的内容」。[Lilian Weng 原文](https://lilianweng.github.io/posts/2023-06-23-agent/#component-two-memory)

## 程序性记忆支持行动与方法

程序性记忆，Procedural Memory，回答「怎样做」，涉及技能、行动规则与方法。

在人类记忆中，会骑自行车是一种技能；能够背诵操作步骤，不等于已经掌握平衡能力。在 Agent 的功能框架中，程序性记忆用于支持行动和决策，可以涉及模型中的隐含能力或代码中的显式程序。[Lilian Weng 原文](https://lilianweng.github.io/posts/2023-06-23-agent/#component-two-memory)、[CoALA 原文](https://arxiv.org/html/2309.02427v3#S4.SS1)

例如一种辅导方法：

```text
确定本轮只讲一个问题
        ↓
解释定义并给出例子
        ↓
检查理解
        ↓
根据反馈补讲或继续
```

重点是组织下一步行动。「合理」不是分类条件，被保留的方法也可能有缺陷，是否有效需要另行判断。

## 同一次经历可以支持不同结果

教学假设：一次辅导中，用户表示概念太多；改成每次一个概念后，用户确认理解。

| 类型 | 可能保留的内容 | 之后的作用 |
| --- | --- | --- |
| 情景记忆 | 那次辅导发生了什么以及调整结果 | 参考案例 |
| 语义记忆 | 用户在这次反馈中表现出逐节讲解的偏好 | 理解用户 |
| 程序性记忆 | 后续逐节讲解并检查理解 | 指导行动 |

从一次反馈推得用户偏好，包含提炼或判断，应保留依据与适用范围。系统不一定自动生成三种内容；一次经历、知识结论与操作方法是不同结果。

「长期」与「情景」不冲突，前者涉及保持范围，后者涉及内容与功能。一段长期保留的经历也可以被取出参与当前工作记忆中的处理。

## 用户理解与第一次澄清

用户将三类理解为：情景记忆是某一次事情，语义记忆类似 Fact，程序性记忆是一组流程、经验或方法。

共同澄清：

1. 情景记忆更准确地指一次经历及其情境。
2. 事实是语义内容的一种，概念、定义与关系也属于知识。
3. 「经验」有不同含义：具体经历偏情景，知识结论偏语义，行动方法偏程序性。

用户随后确认理解，并继续学习。三类是本轮采用的 Agent 长期记忆功能框架，不表示已经穷尽人类记忆分类。

## Agent 分类与隐性记忆的补充澄清

用户进一步提出：Agent 记忆主要是语义、情景、程序性三类，因为隐性记忆无法以文本表述，所以框架里常见 Fact、Skill、Semantic。

其中「三类可作为 Agent 长期记忆的主要功能视角」成立，但原因需要修正：**人类隐性记忆强调使用不依赖有意识回想学习经历，不是以能否文本表达作为分类标准。** 可以用文字描述骑车方法，但文字描述不等于实际掌握的平衡技能。[Squire 与 Dede](https://pmc.ncbi.nlm.nih.gov/articles/PMC4355270/)

Agent 借用程序性记忆概念时，关注支持行动的能力与程序，不要求具有与人类隐性技能相同的生物机制，也不要求无法用文字或代码表达。长期记忆的三类功能之外，当前处理仍涉及工作记忆。

## 功能分类与框架名称

| 名称 | 本轮采用的解释与边界 |
| --- | --- |
| Fact | 一条事实内容或记录，可能表达知识，也可能记录具体事件；不能仅凭标签认定为语义记忆 |
| Skill | 技能或可复用方法，可能承担程序性记忆的作用，仍需看项目定义与实际用途 |
| Semantic | 可能指知识型记忆，也可能出现在语义检索的命名中，不能只凭名称确定职责 |

**功能分类回答内容用来做什么，记录名称回答项目怎样组织内容。两者可以对应，但不一定一一对应。** 这套理论可用于解释框架设计；某个项目是否直接源自它，需要作者说明或其他证据，不能仅凭命名判断历史来源。

本轮修正后的表述是：Agent 的长期信息可以按经历、知识和做法来理解；框架中的事实、事件、技能等对象，可能是这些功能的具体载体。
