# 来源证据与推断

> 第④节第一部分。已共同阅读并通过讨论确认理解，记录日期：2026-10-12。返回[[00_学习目录|学习目录]]；关联[[09_记忆系统核心职责讨论]]。

**抽象和推理可以产生新结论，但不能凭空产生新的证据；结论应能追溯到实际支持它的来源。** 保存成功不代表内容已经得到证实，同一份证据的多个衍生版本也不构成多份独立证据。

## 直接记录与推断的区别

教学假设：用户学习某个概念时，要求先看例子，随后表示理解了。

| 保存内容 | 性质与直接支持的范围 |
| --- | --- |
| 用户这次要求先举例 | 记录这次互动中的要求 |
| 用户表示看完例子后理解了 | 记录用户对理解情况的陈述 |
| 用户学习抽象概念时通常更适合先看例子 | 根据互动形成的推断，开始概括其他类似情况 |

三种内容并不支持相同强度的结论。前两条与具体互动相联系，第三条的范围更广，需要检查依据与适用条件。

从经历形成语义记忆，改变了内容的组织方式，不会自动提高其真实性。上述例子不表示已对用户所有学习活动进行了观察。

## 主张与证据

主张，Claim，是系统认为成立的内容；证据，Evidence，是能够支持或挑战这个内容的信息。

例如，主张是「先举例通常有助于用户理解抽象概念」；依据是几次相关互动中，用户要求例子，并在之后表示理解。

这些信息可以支持一个暂时的学习策略，还不足以证明「用户理解任何内容都必须先看例子」。可信程度既与依据有关，也与从依据到结论跨了多远有关。有证据与已经确定，需要分开理解。

**记忆可以保存推断，但应当保留它仍是推断这一性质。**

## 来源与形成过程

Provenance 在这里指来源与形成过程：内容来自谁或什么材料，经过哪些处理，又依据哪些信息形成。

W3C PROV 描述数据产生所涉及的实体、活动和参与者，用来源信息帮助评估质量、可靠性与可信程度。[PROV 概览](https://www.w3.org/TR/prov-overview/)

对归纳结论，可以追溯「原始互动 → 对互动的整理 → 得出的结论」。这样遇到新信息时，就能检查原记录是否误读、归纳是否丢失条件，以及新经历是否支持或限制旧结论。

来源清楚不保证结论正确，但使结论更容易检查和修正。

## 重复记录不等于新增证据

假设只有一次互动：「用户这次要求先举例」。系统将它保存为原始记录，生成摘要，再从摘要形成偏好结论。

三条记录可能仍然只依赖同一次互动。把它们当作三次独立支持，会高估结论的可信程度。

还可能出现循环：推断被保存后，再次取出并当作新增依据，继续强化同一个推断。整合时因此不仅需要判断内容是否重复，也需要追溯它们是否来自同一份证据。

## 本次共同讨论

用户在理解上述关系后提出：

> 记忆可以抽象、推理延伸，但是不管是抽象出来的、推理延伸的，或者主张，这些都只有一个真相源，就是那一次互动。

讨论明确了两个范围：

1. 在上述单次互动的例子中，多层衍生内容确实依赖同一次原始互动；实际结论也可以依赖多次互动或多种来源。
2. 「原始证据来源」比「真相源」更准确。记录用户说自己理解了，直接支持这次陈述；能否独立应用概念，还需要其他表现来判断。

用户特别认可本节核心句，并总结：

> 你可以通过抽象 推理产生新的结论 但结论永远没法等于证据 (也就是真實来源)

**本节保留这一总结所强调的溯源原则：推理结论不能自动替代原始证据，也不能仅因被保存、复述或再次检索，就算作新增的独立证据。**

这里的范围是区分原始依据与衍生内容，不把「结论永远不能在任何推理中作为依据」作为一般规则。已有结论可以成为后续推理的前提，但其证据依赖仍应追溯到实际来源。

## 在三类核心职责中的位置

| 职责 | 可靠性方面的作用 |
| --- | --- |
| 编码 | 保留内容性质、来源与关键条件 |
| 整合与维护 | 检查依据、控制概括范围，根据新证据修正结论 |
| 检索 | 带回结论与必要依据，供当前任务判断是否采用 |

用户确认理解，并明确授权记录本节及共同讨论，特别突出抽象与推理不自动增加证据这一原则。
