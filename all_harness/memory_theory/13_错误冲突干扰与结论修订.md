# 错误冲突干扰与结论修订

> 第④节第三部分。已共同阅读并讨论确认，记录日期：2026-10-13。返回[[00_学习目录|学习目录]]；前一部分为[[12_时间有效性与适用条件]]。

**发现记忆的问题，需要检查内容、适用范围和证据依赖。** 修正一条原始记录之后，还要检查建立在它上面的结论；有其他支持的结论不必一律删除，但需要重新评估。

## 错误冲突与干扰的区别

| 概念 | 含义 | 教学例子 |
| --- | --- | --- |
| 错误 | 记录或结论与其描述的情况不符 | 把「本周每天只能学习 20 分钟」改成永久限制 |
| 冲突 | 同一对象在相同时间与条件下，两个主张不能同时成立 | 同一服务版本与同一配置条件下，默认端口分别被记成 8000 和 9000 |
| 干扰 | 某条记忆妨碍当前取用或判断 | 新版本任务中反复沿用旧版本的操作方法 |

三者可以重叠，但不能混为一谈。发现冲突，不代表已经知道哪一条错；发生干扰，也不代表旧记忆在原来的情境中就是错误的。

## 先判断是不是真正冲突

比较两条记忆之前，先检查它们是否描述相同对象、时间、版本与环境。如果一个端口属于旧版本，另一个属于新版本，两条历史记录可以同时成立。

如果条件一致而主张仍不能同时成立，再比较原始来源与支持关系。文档描述、运行时观察、用户陈述与系统推断表达的内容可能不同，需要判断它们究竟支持什么。

依据不足时，可以保留「尚未解决的冲突」，不必为了给出唯一答案而任意覆盖其中一条。

## 信念修订与衍生结论

信念修订，Belief Revision，在这里指系统根据新信息调整接受的主张。它不要求 Agent 具有人类的主观信念。逻辑理论研究过纳入新命题与撤回已有命题的区别；本节只借用这一基本问题，不展开具体公理或算法。[On the Logic of Theory Change](https://doi.org/10.2307/2274239)

教学假设：系统记住「某次超时通过重启服务解决」，并进一步归纳出「遇到超时应当重启服务」。后来发现，那次排查还修改了网络配置，最初记录遗漏了这一点。

此时，只改原始记录还不够。系统还需要检查「重启解决了超时」这一因果判断，以及根据它形成的操作方法。共同发生的改动没有被分清，原来的单一原因解释就需要重新评估。

可能的处理包括保留仍有充分支持的结论、降低接受程度、缩小适用范围，或撤回缺乏支持的结论。选择取决于剩余证据支持什么，不由记录数量直接决定。

## 用户关于剩余证据的判断

用户回答理解检查时提出：

> 应该是要检查他形成的结论是否还有其他证据支撑。如果确实就他孤零零一个支撑这条结论，那肯定要推翻了。但是如果还有其他证据支撑结论，那依然可以视情况采用，或者降低权重等等。

这里的「孤零零一个」是在讨论原先那条依据已经被发现失效的情形。共同确认的原则是：**先检查结论剩余的支持，再决定怎样处理结论。**

对「推翻」补充的边界：唯一依据失效，应撤回原来基于它的接受，但这不自动证明相反结论成立。例如，不能继续据此断言「重启解决了超时」，也不能仅凭这一点断言「重启一定没有作用」。

还有其他依据时，需重新判断它们是否充分、适用且独立。三个摘要都来自同一次互动，仍然只有一个原始来源；派生记录变多没有增加独立观察。来源与派生关系见[[11_来源证据与推断]]。

用户提到的「降低权重」可以理解为减少它对当前决策的影响；是否采用数值置信度或检索排序权重，属于后续实现选择。

## 干扰与当前任务

旧版本操作方法可以是正确的历史记忆，却不适合当前版本。如果它持续主导当前回答，就可能构成使用上的干扰。

人类记忆实验中，练习提取部分项目可能损害对相关、未练习项目的后续提取。这为理解记忆之间的影响提供了研究例子，不意味着 Agent 与人脑采用相同机制，也不意味着每次提取都会导致遗忘。[Remembering Can Cause Forgetting](https://doi.org/10.1037/0278-7393.20.5.1063)

在 Agent 中，本节关注的是当前任务是否受到不适用、误导或错误关联的记忆影响，而不是把人类实验机制直接移植到软件系统。

## 三类职责与继续位置

| 职责 | 在可靠性问题中的作用 |
| --- | --- |
| 编码 | 保留上下文、条件与来源，减少错误表达 |
| 整合与维护 | 检查冲突、修订主张，并检查依赖它们的结论 |
| 检索 | 根据当前对象与条件选择适用内容，减少旧记忆干扰 |

本节的例子均为教学假设，不是用户个人事实。用户已通过剩余证据的讨论确认理解，并授权增量写入。
