# 记忆 RAG 与上下文管理

> 收尾一。已共同阅读并确认理解，记录日期：2026-10-13。返回[[00_学习目录|学习目录]]；前一部分为[[17_记忆系统的评估]]。

**记忆、RAG 与上下文管理关注不同问题，可以在同一系统中共同工作。** 不能只根据项目名称判断它承担了哪些职责，也不能把移出当前输入等同于删除长期记忆。

## 三个概念关注的问题

| 概念 | 主要关注什么 |
| --- | --- |
| 记忆 | 信息怎样跨时间保留、维护，并在以后影响行为 |
| RAG 检索增强生成 | 怎样检索已有信息，用它支持当前生成 |
| 上下文管理 | 当前这次模型调用应看到哪些信息，以及怎样组织它们 |

这里的记忆重点是此前讨论的长期记忆；工作记忆仍参与当前处理。三者不是互斥的系统类型。

## RAG 与记忆的取用和维护

教学假设：Agent 保存了某人上周和本周的学习安排，当前检索本周安排并据此生成计划。长期记忆提供历史信息，检索增强生成帮助利用它回答当前问题。

最初怎样提取时间与条件、新信息怎样影响旧安排，以及原始依据错误后怎样修订衍生结论，仍需相应形成与维护机制。「检索信息来支持生成」本身没有完整规定这些工作。

RAG 也可以只检索固定手册回答问题，不必在每次互动后学习用户的新经历。但资料库同样可以承担记忆功能：原始 RAG 论文把模型参数和外部检索库分别称为参数化记忆与非参数化记忆；CoALA 把用于检索的知识文本视作语义记忆的一种形式。[RAG 原论文](https://arxiv.org/abs/2005.11401)、[CoALA 第 4.1 节](https://arxiv.org/html/2309.02427v3#S4.SS1)

因此，判断系统时要看承担的功能与信息流，而不只看 Memory 或 RAG 的名称。

## 当前上下文与长期保存

假设长期存储有一千条记录，当前任务只是安排本周学习。模型输入可能只需要本周时间、相关学习偏好、当前目标与必要的来源和条件。

上下文管理考虑这些信息怎样选择和组织，也可能涉及摘要、压缩与长度预算。

从当前输入中移除某条记忆，不等于从长期存储中删除它。它可能只是本次不需要，以后仍能取用。

同样，把聊天压缩成摘要，不自动证明摘要已得到长期保存。摘要表达什么、保存在哪里以及以后能否取用，是不同问题。

模型输入可以承担部分工作记忆功能，但 Agent 的工作记忆不必全部放进当前输入。CoALA 允许工作记忆跨调用保持，再从其中选择一部分组成模型输入。[CoALA 第 4.1 节](https://arxiv.org/html/2309.02427v3#S4.SS1)

## 在同一任务中配合

教学假设：某人本周告诉 Agent「每天可以学习 40 分钟」。系统可以完成：

1. **记忆形成与维护**：保存陈述、时间范围和来源，处理它与旧安排的关系。
2. **检索**：安排本周计划时找到对应记录。
3. **上下文管理**：把需要的内容与条件组织进当前模型输入。
4. **生成与使用**：据此提出计划，这一环节可以采用检索增强生成。

这是职责配合的教学拆分，不要求固定的模块或顺序，也没有为此前的三类核心职责额外增加一套分类。它说明记忆职责怎样与当前模型输入和生成过程衔接。

## 理解确认与继续位置

理解检查：上周安排从本次模型输入中移除，但仍保存在长期存储里，能否直接说明系统已经遗忘上周安排？

用户回应「ok，写入，然后讲下一部分」，确认本节并授权记录，没有另行给出逐项答案。该例子的分析是：不能；本次不呈现、以后仍可取用，与长期删除或不可访问不同。

上述学习安排均为教学假设，不是用户个人事实。
