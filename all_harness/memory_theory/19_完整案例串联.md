# 完整案例串联

> 收尾二。已共同阅读并确认理解，记录日期：2026-10-13。返回[[00_学习目录|学习目录]]；前一部分为[[18_记忆RAG与上下文管理]]。本轮约定的理论入门与两个收尾小节均已完成。

**用同一次学习过程，可以串起记忆分类、编码、整合维护、检索、可靠性与评估。** 关键是保留内容与条件，区分经历和推断，并根据当前任务判断记忆能支持什么行动。

本案例中的小林是虚构学习者。所有时间安排、偏好、反馈与系统行为都是教学假设，不是用户个人事实或真实评测结果。

## 第一次互动与编码

第一周，小林告诉 Agent：

> 这周比较忙，每天只能学习 20 分钟。学抽象概念时，我喜欢先看例子。

| 内容 | 适用范围 |
| --- | --- |
| 每天可学习 20 分钟 | 第一周，因为较忙 |
| 喜欢先看例子 | 学习抽象概念时，是当事人的偏好陈述 |

如果编码成「小林每天只能学习 20 分钟，任何任务都必须先讲例子」，就扩大了原话范围。编码需要保留时间、任务条件和来源性质。

这次互动可以形成承担不同功能的内容：

1. **情景记忆**：第一周，小林作出了这次陈述。
2. **语义记忆**：小林自述本周的时间限制与特定情境下的学习偏好。
3. **程序性记忆**：据此形成暂定讲解方法，学习抽象概念时先给例子，再解释定义。

经历、关于小林的知识和指导行动的方法可以相互关联，不是要求每句话只能放进一个互斥盒子。程序性方法是进一步形成的安排，需要保留依据和适用条件。

分类基础见[[03_情景记忆语义记忆与程序性记忆]]；编码与表示见[[05_编码与记忆表征]]及[[14_记忆表示与理论层次]]。

## 反馈与衍生结论

第一周中途，Agent 用先例子、后定义的方式讲解。小林反馈：

> 这样我感觉更容易理解。

系统可以保存新的互动经历，并形成暂定判断：对小林学习这类抽象概念，先例子、后定义可能有帮助。

原始依据支持的是「小林报告这次讲解让他感觉更容易理解」。它没有独立证明已经掌握知识，也没有证明方法适用于所有任务。

推断可以保存并关联到反馈，之后获得新支持或反例时重新评估。原始反馈、反馈摘要和衍生建议不能计成三次独立验证。

**推理能产生新结论，但结论不能自动变成新的独立证据。** 相关原则见[[11_来源证据与推断]]。

## 新信息与整合维护

第二周，小林又说：

> 这周每天可以学习 40 分钟。不过，讲公式推导时，我想先看定义。

时间安排与讲解偏好需要分别处理。

第一周的 20 分钟仍是历史记录，第二周的 40 分钟支持当前安排。两者描述不同时间，不构成真正冲突；旧记录可以保留，但不能继续作为第二周的限制。

讲解偏好得到细化：一般抽象概念先看例子；公式推导采用小林后来表达的、更具体的先看定义偏好。此前的一般规则不应继续无条件覆盖这个特定情境。

| 任务情境 | 当事人表达的偏好 |
| --- | --- |
| 一般抽象概念学习 | 先看例子 |
| 公式推导 | 先看定义，作为后来明确的具体情境偏好 |

对应程序性方法也应细化，不能机械执行「所有内容一律先举例」。整合与维护可以改变当前状态，也可以收窄已有结论的范围，不要求每次新信息进入都删除旧内容。

时间与修订基础见[[12_时间有效性与适用条件]]及[[13_错误冲突干扰与结论修订]]。

## 当前任务与取用

第二周，小林提出：

> 帮我安排今天的学习，重点是理解一个公式的推导。

系统先明确需要今天可投入的时间与公式推导的讲解方式，再找到候选，按时间和任务条件选择。

当前模型输入可以组织成：

> 当前任务：理解一个公式的推导。  
> 时间依据：小林第二周自述每天可以学习 40 分钟。  
> 讲解偏好：公式推导先看定义。  
> 相关知识：需要讲解的定义、公式与推导材料。

人物、时间、关键词或向量可以提供查找线索。查找方式不改变原始记录的条件与来源。模型可以据此先解释定义、逐步推导，再按需要补充例子。

长期记忆保留历史信息，检索取得相关内容，当前工作记忆支持计划和讲解。上下文管理决定哪些内容进入模型输入；利用检索材料生成讲解，可以采用 RAG 的方式。

索引与取用见[[15_索引与向量检索]]及[[16_候选记忆的选择与使用]]；概念关系见[[18_记忆RAG与上下文管理]]。

## 过程与最终效果的评估

| 检查位置 | 具体问题 |
| --- | --- |
| 编码 | 是否保留第一周、第二周与公式推导等条件 |
| 整合与维护 | 是否更新当前时间安排，并细化讲解方法 |
| 检索 | 是否取得第二周安排和公式推导偏好 |
| 理解与使用 | 是否采用取得的信息，没有机械沿用旧方法 |
| 最终效果 | 是否符合时间约束，并帮助完成当前学习目标 |

找到所有记录不能代替后续检查。小林说讲得清楚，也不能单独证明已经掌握公式。评估可以根据目标要求解释关键步骤或完成应用题，具体思路见[[17_记忆系统的评估]]。

## 理解确认与完成范围

最后的理解检查：收到「公式推导先看定义」之后，是否必须删除「学习抽象概念时喜欢先看例子」，还是可以按任务条件保留两者？

用户回应「懂了，可以写入，到这里是不是都讲完了」，确认理解并授权记录，没有另行给出逐项答案。该例子的分析是：可以按任务条件保留，并让公式推导采用更具体的偏好；无需一律删除原有偏好。

**本轮约定的①至⑤节理论入门与两个收尾小节均已讲解、确认并写入，没有剩余的预定讲解小节。** 这不表示穷尽记忆研究，也不表示 Hindsight 组件或源码已经读完。

之后对照框架时，可以沿着三个问题阅读：输入在哪里形成记忆，新旧信息在哪里被处理，当前任务怎样取得并使用这些记忆。Fact、Reflection、Skill、Consolidation、Recall 等名称需要结合框架自己的定义和实际职责判断。
