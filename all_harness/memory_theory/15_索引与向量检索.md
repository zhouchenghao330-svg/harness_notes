# 索引与向量检索

> 第⑤节第二部分。已共同阅读并确认理解，记录日期：2026-10-13。返回[[00_学习目录|学习目录]]；前一部分为[[14_记忆表示与理论层次]]。

**记忆表达了什么，与系统怎样找到它，是两个相关但不同的问题。** 表示保留内容及理解所需的信息；索引为查找预先组织数据。向量是一种表示，向量检索是一种查找方式，向量索引则是帮助组织搜索的数据结构。

## 表示与索引的职责

教学假设：系统保存「某人表示，本周因为较忙，每天可学习约 20 分钟；下周需要重新确认」。这段记录表达了内容、条件与来源。

如果系统有十万条记录，需要查找这个人的学习安排，就要考虑如何根据当前问题定位到相关记录。

索引是为查找预先组织的数据结构。例如，倒排索引组织「某个词出现在哪些记录中」的对应关系，让系统查询这个词时能定位相应记录，减少逐条检查。[Introduction to Information Retrieval](https://nlp.stanford.edu/IR-book/html/htmledition/a-first-take-at-building-an-inverted-index-1.html)

这里按职责区分表示与索引。索引本身也表达了一部分信息，二者不是绝对隔离的物理层次。

## 同一条记忆的多种查找线索

| 当前问题 | 有用的查找线索 |
| --- | --- |
| 这个人的学习安排是什么 | 人物标识 |
| 本周有哪些限制 | 时间范围 |
| 他最近是不是没多少时间学习 | 内容含义 |

同一条记忆可以通过多种方式被找到。编码保留人物、时间与内容；索引利用其中一些信息组织查找；检索根据当前问题选择方式，取得相关记录。

如果编码时已经丢掉「本周」，之后建立时间索引也不能凭空恢复这个条件。

没有索引也能检索，例如逐条检查记录。索引改变查找的组织方式与效率；某些近似索引还可能影响最终找到哪些结果。

## Embedding 与向量索引

Embedding，嵌入表示，在这里指把文本转换成向量，也就是一组数字。用于语义检索的模型让向量之间的相似度或距离有助于判断文本的语义关联。

教学假设：记忆是「本周每天只能学习 20 分钟」，查询是「最近能投入多少时间学习」。两者措辞不同，但语义检索模型可能使它们的向量较接近。Sentence-BERT 研究了能够通过相似度比较的句子向量表示。[原论文](https://arxiv.org/abs/1908.10084)

| 概念 | 做的事情 |
| --- | --- |
| 生成 embedding | 把内容转成向量表示 |
| 向量检索 | 比较查询向量与记录向量，寻找接近的结果 |
| 建立向量索引 | 预先组织向量，帮助搜索接近的结果 |

**有了向量，不代表已经建立了向量索引。** 系统可以逐个比较所有向量，也可以利用索引加速查找。

pgvector 支持直接进行精确近邻搜索，也支持添加近似索引，以部分召回率换取速度。这里的精确是相对于向量距离计算的结果，不表示它已准确判断记忆的真实性或适用性。[官方索引说明](https://github.com/pgvector/pgvector#indexing)

本节先区分这些职责，不展开具体索引算法。关于邻居图、增量插入、随机分层、构建与查询参数，以及大规模数据下的内存局限，见[[15.1_HNSW向量索引的构建过程|HNSW：构建过程与规模局限]]。

## 相似度与当前可用性

向量相似度帮助找到语义相关的候选，不直接证明记录真实、当前有效或适用于当前对象与环境。

例如，「旧版本中重启服务解决过超时」可能与「当前版本发生超时」高度相关，但是否采用旧方法还需要检查版本、条件与原始依据。

一次取用可以理解为：

> 利用查找线索找到候选记录 → 检查记录表达的内容与条件 → 决定它能怎样支持当前任务。

这是理解职责的教学拆分，不要求所有框架都采用固定顺序或分成独立模块。索引帮助定位；完整取用还需要判断。可靠性与适用范围见[[12_时间有效性与适用条件]]及[[13_错误冲突干扰与结论修订]]。

## 理解确认与继续位置

理解检查：系统给每条记忆生成 embedding，但查询时仍逐个比较所有向量，它是否一定建立了向量索引？

用户回应「懂了，写入，然后讲下一部分」，确认理解并授权记录，没有另行给出逐项答案。该例子的分析是：已经有向量表示，也在执行向量检索，但不一定建立了向量索引。

学习安排与服务排查均为教学假设，不是用户个人事实。
