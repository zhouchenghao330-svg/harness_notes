## 1. 同名定义按当前 Agent 的范围选择

DSH 的共享工具注册表保存全局和各范围的注册。查找某个 Agent 的工具时，沿其实际范围链组合定义；较近范围的同名定义覆盖较远范围。绑定 Preset 的常见顺序是：全局 → Preset → Agent 本地。

以下是假设三份同名工具已经注册的示例，不是默认 Web 工具清单。暂不考虑限制和条件启用。

```text
全局：read 的通用版本
    ↓
某个 Preset：read 的 Preset 版本
    ↓
该 Preset 下的 Agent A：read 的会话专属版本
```

| 使用者 | 实际选中的 read |
| --- | --- |
| Agent A | Agent A 本地版本 |
| 同 Preset 下、没有本地覆盖的 Agent B | Preset 版本 |
| 不继承该 Preset、也没有其他局部覆盖的 Agent C | 全局版本 |

这不会改写全局定义，不会让 B 看到 A 的本地工具，也不会把三份同名定义同时暴露给同一 Agent。这里选择的是工具定义，其中包括模型说明和相应执行行为，不只是改工具名称。

跨范围覆盖不依赖插件加载先后；同一范围内重复注册同名工具则报错，不采用后注册覆盖。`run_code` 是执行器保留名称，不能作为普通工具注册或覆盖；其完整行为留到工具执行器组件。

## 2. 继承工具限制与本地贡献

当前范围的 allow/deny 规则限制从上层继承的工具，多份限制取交集；当前范围自己登记的工具随后加入，不被这一层继承过滤移除。

例如 Preset 提供 read、bash，Agent A 设置继承白名单只允许 read，并本地注册 report，则 A 可以得到 read、report，不能继承 bash。同 Preset 下的 B 不受 A 的限制影响。

限制也适用于从 Preset 等祖先范围继承的工具，不只作用于全局层。祖先限制会参与后代的继承过滤。工具限制针对范围内的名称选择，不是任意插件代码的安全隔离。

实际顺序可以概括为：

```text
合并全局和祖先贡献，较近的祖先覆盖较远定义
                    ↓
对继承定义应用范围链上的限制
                    ↓
加入当前范围自己的贡献，同名时采用本地定义
                    ↓
得到该 Agent 当前的可见定义
```

## 3. 可见之后，还要决定本步是否接纳

模型调用前，循环读取当前模型选择，解析该 Agent 的可见工具，再检查各工具注册时提供的条件。条件按本步检查，不能把“已经注册”直接等同于“当前一定提供给模型”。

这里的本步是默认循环的一次逻辑执行步骤，包含模型请求及其工具处理，可能在内部重试模型请求。工具选择由该步骤持有，直到本步结束并释放。

本步选择记录接纳的工具定义及注册身份。后续模型工具说明、执行器程序绑定和工具执行使用相应选择，而不是只在执行时按名字寻找任意最新实现。

如果较近范围的 read 覆盖了全局 read，但它的条件本步返回 false，则本步不接纳 read，不会再自动尝试全局版本。覆盖与条件启用是先后两个阶段，不构成备用实现链。

条件变化也不会给已经准备好的步骤自动新增工具：本步没有接纳某工具，即使稍后条件变成 true，也需要后续步骤重新选择。

## 4. 执行前还检查注册是否仍然有效

本步选择不是对工具存活的无条件保证。读取该选择时会重新对照当前可见定义与原始注册身份。工具被注销、被另一份定义覆盖，或继承限制变化，可能让原先接纳的工具当前不可执行。

```text
模型请求使用旧 read 的说明
             ↓
旧 read 注销，同名的新 read 注册
             ↓
旧请求返回 read 调用
             ↓
旧步骤拒绝该调用，不会自动执行新 read
             ↓
后续步骤重新准备，才有机会接纳新注册
```

即使重新注册使用的是同一个定义对象，注册身份也已经不同，旧步骤不能因此接纳它。某项临时限制解除后，原本已经接纳且身份仍有效的工具可以重新可用；所以不能把本步选择描述成完全冻结的实时工具清单。

选择只属于请求它的 Agent，不能拿给另一个 Agent 使用。步骤释放选择后，不能再次用它执行工具。

## 5. 与下一项机制的区别

| 需要回答的问题 | 所属机制 |
| --- | --- |
| 当前 Agent 使用哪份同名工具定义？ | 范围继承、覆盖与限制 |
| 当前步骤接纳哪些工具？ | 条件启用与本步选择 |
| 返回调用时，原注册是否仍有效？ | 选择与当前注册身份复核 |
| 工具函数里访问的是哪个服务对象？ | 服务依赖与实例隔离，见 02.4 |

选择了不同 read 定义，不保证文件系统服务也变成另一份实例。工具选取和服务查找必须分开分析。
