## 1. 定位：已有钩子与中间件知识在 DSH 中的对应

DSH 在运行时机上提供钩子，插件登记回调参与处理；`agent/pre-step` 等扩展点采用中间件链。范围路由用于筛选本次事件可以调用哪些监听器。这是多套插件组合共存的自然工程配套，不作为新的 Agent 核心算法展开。

| 机制 | 回答的问题 |
| --- | --- |
| 钩子 | 在什么运行时机允许插件参与？ |
| 中间件 | 多个处理者怎样委托、包装或提前结束处理？ |
| 事件范围路由 | 当前 Agent 的这次事件允许哪些监听器参与？ |
| 服务实例隔离 | 处理插件调用服务时连接哪份对象？ |

组件实例可以保存不同配置，但若回调登记在共享事件系统上，仍须明确每个回调处理哪些 Agent。普通实现可以显式绑定回调，或在回调内检查对象归属；DSH 把常规范围匹配放到统一的事件分发机制中。

## 2. 普通范围注册的匹配规则

Agent 绑定一份 Preset 运行组合后，其范围与该组合的范围建立父子关系。发出 Agent 事件时，分发器把目标 Agent 与路由标识绑定，再按监听器的登记范围筛选。

```text
全局监听器
│
├─ 日常助手 Preset：自己的压缩监听器
│    ├─ Agent A：可有自己的监听器
│    └─ Agent B：可有自己的监听器
│
└─ 研究助手 Preset：自己的压缩监听器
     └─ Agent C
```

以 A 的事件为例：全局未标记范围的监听器、日常助手 Preset 的监听器和 A 自己的监听器可参与；B 自己的监听器、研究助手 Preset 的监听器和 C 的监听器不会因此参与。同一份 Preset 的监听器可以服务其下的多个 Agent。

匹配当前范围及祖先范围，不表示向后代广播：Preset 范围的事件不会自动调用其下所有 Agent 的局部监听器。底层也支持显式全局监听选项；上述规则描述普通的按范围注册，不将其当成安全沙箱。

## 3. 压缩实例怎样接入

基础压缩实例登记 `agent/pre-step` 监听器。收到本次 Agent 后，使用自身配置调用 `compactIfNeeded()` 检查其上下文，并通过 `next()` 委托后续处理。因此，不同 Preset 的压缩实例既要按服务查找正确连接，也要按事件范围正确参与。

`next()` 在 Cordis 的 waterfall 中表示调用后续处理并返回其结果；不调用就会截断余下处理，包括最终默认处理。同一个 `next()` 不能重复调用。其他事件分发方式并不都采用这一规则，需要按事件自身声明判断。

## 4. 设计判断与保留范围

这项设计的收益是统一管理插件参与范围，减少各插件重复判断 Agent 归属。代价是排查回调未执行时，需要同时检查钩子是否触发、监听器是否登记、登记范围是否匹配，以及前面的中间件是否已经截断处理。

对组件关系固定的 Runtime，显式绑定对象与回调就足够。多套可配置插件组合并存时，统一的范围机制更有组织价值。尚未核对 AI-Human 当前实现，不据此判断它需要新增这套机制。

本节保留为架构机制的简要记录。异常是否中断运行、通知监听器怎样隔离错误、异步工作如何收束和卸载，不由“有钩子”这个事实推导；后续遇到影响核心行为的实际路径再展开。
