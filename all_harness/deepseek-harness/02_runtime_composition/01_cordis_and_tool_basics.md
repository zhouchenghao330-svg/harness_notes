## 1. 从“读取 README”理解工具

把 `read` 理解成一个 Agent 可以使用的函数：它接收文件路径、起始行、读取行数等参数，完成操作后把结果返回给模型。

一个完整工具有两面：模型看到的是名称、用途和参数规则；Harness 中还有对应的执行代码。因此工具不只是协议，工具调用才是模型本次发出的具体操作请求。

```text
模型看到说明：read 可以读取文件，需要提供路径
                      ↓
模型提出请求：调用 read，读取 README.md
                      ↓
Harness 接收请求并执行相应工具代码
                      ↓
工具代码调用文件系统服务读取文件
                      ↓
工具整理结果，Harness 将结果交给模型
                      ↓
模型继续分析或回答
```

“Agent 调用工具”可以作为简写。准确地说，是模型产生调用请求，Harness 执行对应代码；模型自身不直接打开文件。

工具参数校验、审批、并发、取消、结果记录及返回内容的完整处理，仍留在工具体系组件逐项阅读。

## 2. 文件工具与底层文件访问的分工

| 部分 | 用人话解释 |
| --- | --- |
| `read` 工具 | 接收 Agent 的读文件要求，处理读取范围，并整理供模型使用的结果 |
| 文件系统服务 | 提供供其他模块调用的文件操作，例如读取、写入、查看文件信息 |
| `fs-local` | 实际访问运行 DSH 的那台机器上的文件的一种实现 |

这里的“实现”就是实际完成某件事的代码。“提供本机文件系统实现”翻译成具体动作，就是这部分代码通过本机操作系统打开文件、读取内容、写入内容等。

`read` 自身仍有确定的函数体。它把实际访问文件的工作交给文件系统服务；底层由哪种实现提供这项服务，取决于运行配置和已装入的模块。

修改本机文件实现，会影响使用它的工具。也可以另外提供一种文件实现并通过配置选择它，使工具代码保持不变。替换的前提是新实现提供工具所依赖的操作，并遵守相同的输入、返回值、错误及其他使用规则。

“底层可以替换”不表示一次调用会随机挑选执行逻辑；当前运行装入哪种实现，工具就使用相应的能力。这种分层方式也不是 DSH 独有。

本机实现中的 `local` 指“运行 DSH 的当前机器”。DSH 使用的 Node.js 提供了跨操作系统文件操作能力，因此通常不必为 Mac、Windows、Linux 分别重写整套本机文件实现；具体平台差异可以在需要时分别处理。

用远程文件环境替换本机环境，是解释可替换设计的例子。仓库实际支持哪些 provider、怎样配置和保证多个能力使用同一环境，留到能力提供者组件核对，不把这个例子当成已经研究完成的支持清单。

## 3. Cordis 到底是什么

Cordis 是通用的插件化应用框架：开发者写好各块功能，Cordis 提供把它们装入程序、连接起来并管理启动和停止的机制。

插件可以先理解成“可以单独装入程序的一份功能代码”。服务就是“其他模块可以调用的一组功能”。Cordis 不要求这些功能必须与 AI 有关；DSH 把模型、工具、会话和执行循环等 Agent 功能组织成 Cordis 插件。

假设文件模块、工具模块、权限模块和日志模块都已经写好，开发者仍然需要解决模块之间的连接问题。Cordis 主要为这些问题提供统一机制：

| 职责 | 替开发者管理什么 |
| --- | --- |
| 插件装载 | 把某块功能加入正在运行的程序 |
| 服务与依赖 | 让模块找到所需能力，在依赖可用后激活它 |
| 模块通信 | 让模块互相调用，接收通知，或参与检查和处理 |
| 生命周期 | 管理模块启动、停止，以及撤销归属该模块的注册 |

生命周期是“模块从启动到停止的过程”。例如插件启动时注册了某个工具，卸载时需要撤销该工具。开发者必须按 Cordis 的方式登记资源与清理动作，框架才知道该释放什么；不能把它理解成自动发现并清理任意代码产生的资源。

```text
开发者提供具体功能代码
模型调用、工具、文件访问、会话、权限等
                  ↓
将这些功能组织成插件，并声明需要哪些能力
                  ↓
Cordis 管理装载、依赖、通信和退出
                  ↓
组成能够工作的 DSH 程序
```

DSH 提供 Agent 的具体行为；Cordis 提供组织和管理这些功能的通用机制。单独使用 Cordis 不会自动得到 Agent、文件工具或模型调用功能。

## 4. 已经出现的源码名称

正文理解不依赖阅读代码；这里仅保存名称含义，供之后定位。

| 名称 | 含义 |
| --- | --- |
| `Context` / `ctx` | Cordis 给插件使用的运行对象，插件通过它访问服务、注册事件和行为；这里不是发给模型的上下文消息 |
| `ctx.fs` | 通过这个对象访问当前可用的文件系统服务 |
| `inject` | 插件声明自己依赖哪些服务，供 Cordis 管理激活条件 |
| `fs-local` | 提供本机文件访问能力的插件包名称，不是某个操作系统的专有版本 |
