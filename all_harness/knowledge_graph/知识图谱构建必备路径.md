# 知识图谱构建必备路径

> 记录日期：2026-10-15。基于当前 LightRAG 普通文档构图路径整理，讨论后获用户授权写入。本文作为构图主线入口；详细学习进度仍保留在 [[all_harness/knowledge_graph/00_学习目录|学习目录]]。

**先把流程记成：准备材料 → 产生候选 → 检查候选 → 整合知识 → 保存结果 → 验收修正。** 具体实现可以不同，但要知道每一步解决什么问题，不能把模型回答结束当作图谱已经可靠。

开始前先明确业务要回答什么问题，以及需要保留哪些实体、关系、时间、条件和来源。这些表示规则会影响抽取、检查与后续查询。

## 一条完整的构图主线

以下是启用知识图谱构建时的概念流程，不包含所有分支；合并与写入在实际代码中交织进行。

```text
文档进入
   ↓
① 去重、解析、切分，保留原文和来源
   ↓
② 模型抽取实体与关系
   ↓
③ 解析、清理、规范化
   ↓
④ 补抽遗漏，检查候选质量
   ↓
⑤ 对齐并合并已有实体、关系
   ↓
⑥ 更新图、向量索引和来源记录
   ↓
完成存储提交，标记文档处理结果
```

| 步骤 | 要解决的问题 | LightRAG 当前怎样做 |
| --- | --- | --- |
| ① 准备材料 | 避免重复处理；输入大小合适；以后能回查原文 | 文档去重、解析切片，保存片段、来源和片段向量 |
| ② 抽取 | 从文字中提出实体、类型、描述和关系 | 模型按提示词产生候选；匹配请求可复用缓存 |
| ③ 规范化 | 把候选变成程序能处理的数据 | 修复部分格式，清理名称和类型，跳过部分无效记录 |
| ④ 补充与检查 | 减少遗漏，过滤错误或不需要的候选 | 可选补抽一次；提供自定义质量检查接口，默认没有完整事实核验 |
| ⑤ 对齐与合并 | 判断新信息归入哪个对象，避免重复和混淆 | 实体主要按规范化名称聚合，关系按无序实体对聚合；合并描述、关键词与来源，必要时模型摘要 |
| ⑥ 保存与索引 | 让知识可检索、追溯和维护 | 合并中更新图、实体和关系向量及来源跟踪，最后提交存储 |

表中项目行为已核对代码。【Code-verified】

“对齐”是这一环节需要承担的职责，不能把 LightRAG 的名称聚合当成完善的语义消歧。不同别名可能未归一，同名对象也可能混淆。

## 六项需要考虑的机制

这是构建可持续使用的知识图谱时的设计检查表，不表示所有项目都以同一方式完整实现。

| 机制 | 为什么需要 |
| --- | --- |
| **明确的表示规则** | 约定要保留哪些实体、关系、时间和条件，才能判断结果是否合适 |
| **来源追踪** | 信息能够回到支持它的原文，方便核实、修订和删除 |
| **质量检查** | 分别检查抽出的有没有依据、该保留的有没有遗漏 |
| **身份判断与去重** | 避免把同一对象拆成多个，也避免把同名对象混成一个 |
| **增量更新与冲突处理** | 新信息能补充、修订已有内容，而不只是不断追加 |
| **失败恢复与重复执行保护** | 中途失败后可重试，减少重复调用、重复记录和无法清理的残留 |

LightRAG 已有来源记录、缓存、并发控制及恢复依据等机制。例如，修改图之前先持久化文档将涉及的实体与关系候选清单，供失败后的恢复与清理发现贡献。清单是候选范围，不是所有候选已成功写图的证明。【Code-verified】

强实体消歧、完整语义检漏与可靠冲突裁决，不能认为项目默认已经解决。检查接口存在，也不等于已经配置好业务检查规则。

## 检漏放在哪里

```text
抽取候选
   ↓
合并前检查、补漏
   ↓
身份对齐、合并、写入
   ↓
用原文与实际查询验收
   ↓
发现问题 → 修正抽取规则、表示方式或合并规则
```

**合并前检查，减少错误进入图；写入后验收，检查整条链路是否真正保留并用好了信息。** 这是建议采用的工程闭环；不能把它理解为 LightRAG 默认完成了全面的语义验收。

查错从输出回到原文，检查每项陈述的依据；查漏从原文出发，检查约定需要保留的信息在哪里。没有错误不等于没有遗漏，格式通过也不等于事实正确。

LightRAG 的补抽和自定义候选检查位于合并前。补抽不保证无遗漏；一次格式正确的结果仍可能丢失时间、条件或抽错关系。

## 先接通小规模闭环

```text
明确任务与表示规则
        ↓
少量代表性文档 → 抽取 → 检查 → 合并 → 保存 → 查询验收
                          ↑                       │
                          └──────根据问题修正─────┘
```

先用少量材料接通完整链路，再持续改进抽取与整合。无需等抽取器无限完善后才检查查询需求，也不能只凭一段漂亮输出认定系统可靠。
